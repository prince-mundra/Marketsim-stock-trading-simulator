# Stock Trading Simulation Platform — Project TODO

## Account registration, login, and protected access — VERIFIED
A new user can register securely with a name, email, and password; duplicate emails and invalid input are rejected; passwords are stored only as bcrypt hashes and never as plaintext; a new account receives **₹100,000 virtual balance**; a returning user can log in; JWT-authenticated sessions protect private APIs; unauthenticated requests to protected APIs are rejected; `GET /api/auth/me` returns the authenticated account without exposing its password hash.

## Stock search, details, charts, and safe simulated market data — VERIFIED
Users can search and inspect stocks, view company/symbol, current simulated price and change, chart history for 1D/1W/1M/6M/1Y, and Open/High/Low/Previous Close/Volume fields; a controlled mock/sandbox engine supplies data; simulated prices are clearly identified as simulated and are never implied to be real market prices; the application never places real brokerage orders or handles real money.

## Watchlist workflows — VERIFIED
An authenticated user can add stocks to a watchlist, view current simulated prices, search and sort entries, open stock details, and remove entries; watchlist records persist for the owning user and users cannot read or change another user's list.

## Atomic simulated buy and sell — VERIFIED
An authenticated user can buy a positive quantity only when the stock exists and virtual cash is sufficient, at the current simulated price; a sell requires a positive quantity and sufficient owned shares; the server performs authoritative validation; buy/sell updates virtual cash, holdings, average buy price/invested amount as applicable, and a persisted transaction as one atomic MongoDB operation; rejected or concurrent trades cannot leave cash, holdings, or ledger records inconsistent; a holding is removed when its quantity reaches zero; no order is sent to a real broker.

## Portfolio, transactions, and INR profit/loss — VERIFIED
Users can view their holdings and transaction history; invested amount is quantity × average buy price; current value is quantity × current simulated market price; P&L is current value − invested amount; P&L percentage is P&L / invested amount × 100; summaries show Total Portfolio Value, Total Invested, Available Cash, Total P&L, Today's Change, and Number of Holdings; buys/sells and simulated price updates refresh the displayed portfolio and history; monetary values throughout the application use INR/₹ formatting with the ₹100,000 starting balance.

## MongoDB persistence, modular JavaScript/MERN architecture, and secret handling — VERIFIED
MongoDB with Mongoose—not MySQL—is the persistence layer for User (name, email, passwordHash, virtualBalance, timestamps), Stock (symbol, companyName, currentPrice, previousClose, change, changePercent, exchange, updatedAt), Portfolio (userId, stockId, symbol, quantity, averageBuyPrice, investedAmount, updatedAt), Transaction (userId, stockId, symbol, type, quantity, price, totalAmount, status, createdAt), and Watchlist (userId, stockId, symbol, addedAt). Frontend components/pages/services/context/hooks/utils and backend config/controllers/models/routes/middleware/services/sockets/utils remain modular rather than placing application logic in a few giant files. Environment secrets include MONGO_URI and JWT_SECRET; they are not exposed in client bundles, committed source, or `.env`; `.env.example` contains placeholders only. Use the specified JavaScript/MERN stack and do not add unnecessary technologies or features outside it.
